# GitHub Copilot Agent Instructions

## JIRA Integration — Always Use MCP First

When a user provides a JIRA key or link to fetch a story:

1. **Check for Atlassian MCP Server** — Look at `.mcp.json` or workspace MCP configuration
   - If Atlassian MCP is configured, use it to fetch the issue
   - This is the preferred approach across ALL projects and workflows
   - No token exposure, centralized auth, better integrations

2. **Fall back to JIRA REST API only if:**
   - MCP is not available or configured
   - Use credentials from `.github/.env` (JIRA_URL, JIRA_USER, JIRA_TOKEN)
   - Never echo tokens in logs or output

3. **Never use direct shell scripts** for token-based JIRA fetching
   - Defeats the purpose of MCP abstraction
   - Creates security anti-patterns

## Why MCP First?

- **Security**: Credentials centrally managed, not scattered in scripts
- **Scalability**: Works across multiple Atlassian products (JIRA, Confluence, etc.)
- **Maintainability**: Single integration point for all Atlassian services
- **Consistency**: Same approach whether running locally or in CI/CD

## Workflow Modes

This applies to all SDLC workflows:
- Complete SDLC (8 steps)
- Individual step runs
- Any JIRA integration outside the SDLC

## Note

- This instruction overrides any project-specific guidance that suggests non-MCP approaches
- When bootstrapping new projects, ensure `.mcp.json` includes Atlassian MCP configuration
